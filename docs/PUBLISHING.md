# Работа с GitHub-репозиторием

Целевой репозиторий проекта:

<https://github.com/oookosmos/-LC-AC108---Raspberry-Pi4>

Основная ветка: `main`.

## Первичная загрузка подготовленных файлов

В репозитории уже есть первоначальный `README.md`. Поэтому сначала клонируйте его, чтобы сохранить текущую историю и не перезаписывать ветку принудительно.

Откройте Git Bash или терминал с установленным Git и выполните:

```bash
git clone https://github.com/oookosmos/-LC-AC108---Raspberry-Pi4.git
cd -- -LC-AC108---Raspberry-Pi4
```

Скопируйте содержимое подготовленной папки `raspi4-voice-assistant` в эту клонированную папку. Скопируйте также скрытый файл `.gitignore`; он находится в корне подготовленного комплекта. Не копируйте каталог `.git` из другого проекта, если он у вас есть.

Затем проверьте изменения:

```bash
git status --short
```

Должны быть подготовленный `README.md`, `.gitignore`, `docs/` и `scripts/`. Убедитесь, что в списке нет `venv/`, `models/`, `*.wav`, `*.raw`, `*.ko`, `.env`, токенов или приватных ключей.

Добавьте и отправьте изменения:

```bash
git add README.md .gitignore docs scripts
git diff --cached --stat
git commit -m "docs: document LC-AC108 setup and real-time Russian Vosk"
git push origin main
```

После отправки откройте репозиторий и проверьте, что README отображается, а файлы `docs/` и `scripts/` доступны.

## Обновление проекта в будущем

После изменения кода или документации используйте обычную последовательность:

```bash
git status --short
git add README.md .gitignore docs scripts
git diff --cached
git commit -m "Краткое описание изменений"
git push
```

Не используйте `git push --force` для обычной публикации. Перед коммитом проверяйте `git diff --cached`, особенно если добавлялись логи, записи или конфигурационные файлы.

## Что не следует публиковать

- `venv/`, `.venv/` и `__pycache__/`;
- папку `models/` с моделью Vosk и архивы моделей;
- аудиозаписи `*.wav`, `*.raw`, `*.pcm`;
- скомпилированные модули ядра `*.ko` без отдельного решения о публикации;
- `.env`, пароли, access tokens, приватные SSH-ключи;
- конфигурации с личными IP-адресами, SSID и секретами.

Файл `.gitignore` уже содержит основные исключения, но перед каждой отправкой всё равно проверяйте `git status`.
